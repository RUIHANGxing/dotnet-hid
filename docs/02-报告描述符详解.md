# 02 · 报告描述符详解

> 本篇讲"字节级"的规则。配合 `parse` 命令一起看效果最好：
>
> ```powershell
> dotnet run --project src/TouchProbe -- parse
> ```

---

## 1. item 的编码规则（只要记住这一张图）

描述符是一串 item 拼接而成，每个 item 的结构固定：

```
字节 0（前缀）：
   bit 7 6 5 4 | bit 3 2  | bit 1 0
   └─ tag ────┘ └─ type ─┘ └─ size ─┘

   size：0 → 没有数据字节       1 → 1 个数据字节
         2 → 2 个数据字节       3 → 4 个数据字节

   type：0 = Main（主条目，产生数据）
         1 = Global（全局状态，一直有效）
         2 = Local （局部信息，只影响下一条 Main）
         3 = 保留

数据部分：按小端序（低位字节在前）拼成一个整数
```

例：`05 01`
- 前缀 `0x05` = `0000 0101` → tag=0、type=01(Global)、size=01(1 字节)
- 数据 `0x01`
- 含义：`Usage Page = 1`（通用桌面页）

例：`15 81`
- 前缀 `0x15` → tag=1、type=1、size=1；数据 `0x81`
- 因为"逻辑最小值"这个字段是**有符号**的，所以 `0x81` 解读为 **-127**（补码）
  ——这是新手最容易懵的一处：同一个字节，在不同 item 里含义不同。

---

## 2. 三类 item 的全表

### Global（设置后持续有效）

| tag | 名字 | 作用 |
|---|---|---|
| 0x0 | Usage Page | 设定后面 Usage 属于哪一页 |
| 0x1 | Logical Minimum | 数值下限（**有符号**；< 0 说明字段是有符号数） |
| 0x2 | Logical Maximum | 数值上限（有符号） |
| 0x3 / 0x4 | Physical Minimum / Maximum | 物理量的上下限（换算用） |
| 0x5 | Unit Exponent | 单位指数 |
| 0x6 | Unit | 单位编码 |
| 0x7 | Report Size | 每个值占多少**位** |
| 0x8 | Report ID | 报告编号（出现它就说明设备使用报告 ID） |
| 0x9 | Report Count | 这种值连续出现几个 |
| 0xA / 0xB | Push / Pop | 把全局状态压栈 / 恢复 |

### Local（只影响下一条 Main，之后自动清空）

| tag | 名字 | 作用 |
|---|---|---|
| 0x0 | Usage | 给字段一个用途（可以写多条，配合 Report Count 使用） |
| 0x1 / 0x2 | Usage Minimum / Maximum | 一段用途范围（如"按钮 1~3"） |
| 0x7 | String Index | 关联字符串 |
| 0xA | Delimiter | 备用用途集（罕见） |

> **一定要记住**：Main 条目执行完，Local 状态必须清空。忘记清空是初学者写描述符最常见的错误。

### Main（真正产生字段或结构）

| tag | 名字 | 作用 |
|---|---|---|
| 0x8 | Input | 产出一个输入字段 |
| 0x9 | Output | 产出一个输出字段 |
| 0xB | Feature | 产出一个功能报告字段 |
| 0xA | Collection | 开始一个集合（数据是集合类型：1=应用、2=逻辑…） |
| 0xC | End Collection | 结束当前集合 |

Input/Output/Feature 的数据字节是**标志位**：

| 位 | 名字 | 含义 |
|---|---|---|
| 0 | Data / **Const** | 置 1 = 常量（填充位，没有语义） |
| 1 | Array / **Var** | 置 1 = 每个值独立含义（可变字段） |
| 2 | **Abs** / Rel | 置 1 = 相对值（鼠标位移）；0 = 绝对值（触摸坐标） |
| 6 | NullState | 可以表示"无数据" |
| 8 | BufferedBytes | 缓冲字节（少见） |

例：`81 02` = 二进制 `0000 0010` → Data, Var, Abs，即"一个独立的绝对值字段"。

## 3. 位偏移是怎么算出来的

描述符里**不写**"起始位"。系统（和我们）都是这样算的：

1. 从位 0 开始；
2. 每遇到一条 Input/Output/Feature，就占用 `Report Size × Report Count` 个位；
3. 下一条接着往下排；
4. **不同 Report ID 各自从位 0 开始**（它们是不同的报告，互不影响）。

用鼠标示例（无报告 ID）：

| 顺序 | 指令 | 占位 | 结果 |
|---|---|---|---|
| 1 | `75 01 95 03 81 02`（3 个按键） | 1×3 | 位 0~2 |
| 2 | `75 05 95 01 81 03`（5 位填充） | 5×1 | 位 3~7 |
| 3 | `75 08 95 03 81 06`（X/Y/滚轮） | 8×3 | 位 8~31 |

`parse` 命令的第 5 步就是这张表，第 3 步的"解释"列里也会直接写出位偏移区间。

## 4. 动手练习（强烈建议做）

### 练习 1：读懂 `parse` 的输出

跑 `parse`，对着"经典鼠标描述符"，逐行问自己：
- 这一条是 Global / Local / Main？
- 它改变了哪个状态？
- 后面哪一条 Main 用到了它？

### 练习 2：改一个字节，看解析结果怎么变

改 `Descriptor/SampleDescriptors.cs` 里鼠标那段，例如把 `95 03`（Report Count=3）改成 `95 02`，
再跑 `parse`，观察：
- 按键字段变成几个？
- 后面的填充位从 5 位变成几位（提示：为了凑满整字节，填充位必须变多）？
- 位偏移表发生了什么变化？

### 练习 3：把仿触摸板示例的填充位删掉，看会怎样

删掉示例里的 `75 06 / 95 01 / 81 03` 三条（6 位填充），再跑 `parse`：
位偏移会全部前移，你就能直观感受到——**填充位不是可有可无的装饰，它直接影响后面所有字段的位置**。

### 练习 4：和真实设备对照

跑 `caps`，把真实触摸板的字段表和仿触摸板的描述符对照着看。
你会发现真实设备的结构就是示例的"加长版"：

```
[0] Touch Pad（应用集合）                    ← 对应示例里的 05 0D / 09 05 / A1 01
    ├── [1] Finger 逻辑集合
    │      Tip Switch      1 位   位 0
    │      Confidence      1 位   位 1
    │      Contact ID      6 位   位 2~7    ← 6 位刚好装下 0~5 的触点编号
    │      X              16 位   位 8~23
    │      Y              16 位   位 24~39
    ├── [2]~[5] 同样的四个（每个 40 位）
    ... 最后还有 Scan Time（16 位）、Contact Count（8 位）、Button 1（1 位）
```

**真实触摸板的描述符里读不出原始字节？没关系** —— 你在 `caps` 里看到的是同一份信息的"解析态"，
字段的用途、位宽、逻辑范围、所属集合都在。真正需要"字节"的场合（比如你要自己写固件造一个 HID 设备），
用 `parse` 里的示例练手即可，语法完全一样。

## 5. 常见坑（都是真踩过的）

| 坑 | 现象 | 原因 |
|---|---|---|
| 把逻辑最小值当成无符号数 | `15 81` 被读成 129 而不是 -127 | 逻辑最小/最大值是**有符号**字段 |
| 忘记 Local 状态会清空 | 后面的字段没有用途 | 每个 Main 条目后 Local 必须清空 |
| 忽略填充位 | 位偏移集体错位 | 常量字段看不见但占位 |
| 以为报告一定按字节对齐 | 解出来的坐标乱七八糟 | 字段是连续的位流，可能跨字节 |
| 忘了报告 ID 字节 | 解出来的第一个字段永远是错的 | 有报告 ID 时，第 1 个字节是 ID 不是数据 |
| 用 32 位资料里的结构体尺寸 | 程序莫名崩溃（踩坏内存） | 系统结构体尺寸要以实测为准，见 `docs/03` 的"结构体标定" |

## 6. 想更进一步

- **自己写一段描述符**：按"Usage Page → Usage → Collection → (Report Size/Count/Logical/Input) → End Collection"
  的顺序拼一段字节，用 `parse` 验证。写完你就真正会 HID 了。
- **看真实描述符字节**：Linux 上 `cat /sys/class/hidraw/hidraw*/device/report_descriptor`，
  然后用 `parse --file 文件` 解析（I2C 触摸板转不了，USB 设备可以用 WSL + usbipd 转发）。
- **读规范**：USB HID 规范（Device Class Definition for HID）+ HID Usage Tables（hut1_12v2.pdf）。
  有了本项目的经验，这两份文档会从"天书"变成"字典"。
