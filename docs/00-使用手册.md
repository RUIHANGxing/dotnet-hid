## 1. 环境准备

### 1.1 必须：.NET SDK

打开 PowerShell（或 Windows Terminal / cmd），输入：

```powershell
dotnet --list-sdks
```

**期望**：看到一行形如 `10.0.400 [C:\Program Files\dotnet\sdk]` 的输出。

- 如果提示"无法将 dotnet 识别为 cmdlet"或命令不存在 → 去 <https://dotnet.microsoft.com/download> 下载安装 **.NET SDK 10**（选 SDK，不是 Runtime），装完重开一个终端再试。
- 如果版本低于 8 → 建议装个新的；或者按 1.3 改项目文件。

### 1.2 必须：Windows

本项目的核心功能（SetupAPI、hid.dll、Raw Input）都是 Windows 专有 API，**只能在 Windows 上跑**。
（把代码学明白后，可以照着 `docs/01` 的说明在 Linux 上用 `hidraw` 实现同样的事。）

### 1.3 可选：Visual Studio

想要"图形界面 + 断点调试"就装 VS。要求版本能支持 `net10.0`（即 **Visual Studio 2026**）。
如果你只有 VS 2022，把 `src/TouchProbe/TouchProbe.csproj` 里的

```xml
<TargetFramework>net10.0</TargetFramework>
```

改成你机器上装了的版本（例如 `net8.0`）。本项目只用到很基础的语法和 `System.Threading.Channels`，
.NET 6 以上都能编。

### 1.4 拿到代码

```powershell
git clone git@github.com:RUIHANGxing/dotnet-hid.git
cd dotnet-hid
```

没有配 SSH key 就用 HTTPS：

```powershell
git clone https://github.com/RUIHANGxing/dotnet-hid.git
```

## 2. 3 分钟跑起来

```powershell
# ① 编译（第一次会稍微慢一点）
dotnet build

# ② 看看你电脑里有哪些 HID 设备（不需要操作任何设备）
dotnet run --project src/TouchProbe -- list

# ③ 读懂触摸板的协议结构（这是"描述符解析结果"）
dotnet run --project src/TouchProbe -- caps

# ④ 用我们自己写的解析器解析描述符字节（教学示例）
dotnet run --project src/TouchProbe -- parse

# ⑤ 真·实时解码：跑起来后动一下鼠标
dotnet run --project src/TouchProbe -- watch --mouse --plain --verify
```

第 ⑤ 条会持续刷屏，看完按 **Ctrl+C** 退出。

> 小知识：`dotnet run --project src/TouchProbe -- list` 里那串 `--` 是分隔符，
> `--` 后面的参数才会传给我们自己的程序。

## 3. 命令手册：`list`

**作用**：列出系统里所有 HID 设备接口，并标出"这是不是触摸板""我们能不能直接读它"。

```powershell
dotnet run --project src/TouchProbe -- list
```

输出示例（节选）：

```
  #    触摸板  顶层用途                    VID:PID       输入字节  能否直接读  名字
  ----------------------------------------------------------------------------------------
  5            0x01:0x02 Mouse             0x372E:0x103D 8         独占        Gaming 2.4G
  23   ★      0x0D:0x05 Touch Pad         0x2808:0x0106 30        独占        HIDI2C Device
```

**列的含义**：

| 列 | 含义 |
|---|---|
| `#` | 序号。后面 `--device N` 用的就是它 |
| `触摸板` | 带 ★ 表示判定为触摸板（按顶层用途 + 名字判断） |
| `顶层用途` | `用途页:用途`，后面跟英文名。`0x0D:0x05` = 数字化仪/触摸板 |
| `VID:PID` | 厂商编号:产品编号 |
| `输入字节` | 每个输入报告多少字节（0 表示这个集合不上报数据） |
| `能否直接读` | `可读` = 能用 ReadFile 直接读；`独占` = 被系统驱动独占，要走 Raw Input |
| `名字` | 产品名（取不到就显示设备实例 ID） |

## 4. 命令手册：`caps`

**作用**：打印一个设备的**协议结构**——集合树、字段表，以及我们自己推导出的**位布局**。

```powershell
dotnet run --project src/TouchProbe -- caps                 # 默认自动找触摸板
dotnet run --project src/TouchProbe -- caps --device 5      # 指定 list 里的 5 号设备
```

| 参数 | 说明 |
|---|---|
| `--device N` | 指定设备序号；不填则自动选触摸板 |

输出分 5 步，**每一步都是给人看的**：

| 步骤 | 你会看到 | 它在说什么 |
|---|---|---|
| 第 1 步 | 设备路径 / 实例 ID / VID:PID / 名字 | 确认没抓错设备 |
| 第 2 步 | 顶层用途、输入/输出/功能报告长度、字段个数 | 系统的 `HidP_GetCaps` 汇总 |
| 第 3 步 | 集合树（缩进表示层级） | `Digitizer/Touch Pad` 下面挂 5 个 `Digitizer/Finger` = 5 个触点 |
| 第 4 步 | 字段表：报告ID / 位宽×个数 / 用途 / 逻辑范围 / 所属集合 / 数据序号 | 描述符里每一条 `Usage + Logical + Report + Input` 组合的语义 |
| 第 5 步 | **位布局**：位偏移 / 位宽 / 用途 / 逻辑范围 / 类别 | 我们自己推导的"第几位是什么"，**这就是解码报告用的地图** |

> 触摸板的示例结论（你这台机器）：报告 ID = 4，30 字节报告，5 个触点各 40 位
> （Tip Switch 1 位 + Confidence 1 位 + 触点编号 6 位 + X 16 位 + Y 16 位），
> 后面还有扫描时间、触点总数；实际数据 232 位，我们能解释 225 位，**剩下 7 位是填充位**。

## 5. 命令手册：`parse`

**作用**：用我们**自己写的解析器**解析报告描述符的字节流。这是学 HID 最核心的一步。

```powershell
dotnet run --project src/TouchProbe -- parse                    # 解析内置的两个教学示例
dotnet run --project src/TouchProbe -- parse --file 描述符.bin   # 解析你自己的描述符文件
```

| 参数 | 说明 |
|---|---|
| `--file 路径` | 传入描述符文件。支持**二进制**，也支持**十六进制文本**（`05 0D 09 05 ...` 这种） |

输出顺序（每个示例都一样）：

1. **逐段注释**：`偏移 | 字节 | 含义`——每个字节在说什么；
2. **原始字节**：十六进制 + ASCII 对照；
3. **逐条 item**：`偏移 | 字节 | 类型(Global/Local/Main) | 名字 | 解释`；
4. **集合树**：谁包含谁；
5. **字段表**：每条 Input 产出什么字段、位偏移多少、标志位是什么。

内置的两个示例：

| 示例 | 用途 |
|---|---|
| 经典鼠标描述符（52 字节） | 学 item 编码的最基本套路：Global 状态、Local 信息、Main 产出 |
| 仿触摸板描述符（147 字节） | 学报告 ID、每个触点一个逻辑集合、填充位、功能报告 |

> **为什么用示例，不解析我自己的触摸板？** 因为 Windows 把原始描述符字节留在内核里，
> 用户态拿不到（我们实测扫过 4 种缓冲方式 × 256 个功能号，全部失败，过程见 `docs/01` 第 4 节）。
> 真要字节级解析真实设备，用 Linux：`cat /sys/class/hidraw/hidraw*/device/report_descriptor > d.bin`，
> 再 `parse --file d.bin`。

## 6. 命令手册：`watch`（最核心）

**作用**：实时读取设备的原始输入，解码成人类能读的字段。

### 6.1 全部参数

```powershell
dotnet run --project src/TouchProbe -- watch [选项]
```

| 参数 | 作用 |
|---|---|
| `--mouse` | 目标是鼠标（相对位移，画指针轨迹图）。不带则自动选触摸板 |
| `--async` | 用 **Task + Channel 异步管线**（学 C# Task 的重点示范，见 `docs/03` 第 5 节） |
| `--device N` | 手动指定设备序号（`list` 里的 #） |
| `--plain` | 逐行滚动打印（适合重定向到文件 / 慢慢看） |
| `--raw` | 只打印原始十六进制，不解码 |
| `--verify` | 额外打印"我们自己按位算的值 vs 系统解码的值"对照表 |

### 6.2 五种推荐跑法

```powershell
# ① 鼠标 · 逐行 + 对照表（最推荐先跑这个）
dotnet run --project src/TouchProbe -- watch --mouse --plain --verify

# ② 鼠标 · 全屏刷新，带字符轨迹图
dotnet run --project src/TouchProbe -- watch --mouse

# ③ 鼠标 · 异步版（Task/Channel）
dotnet run --project src/TouchProbe -- watch --mouse --async

# ④ 只看原始字节（不解码），适合喂给别的工具
dotnet run --project src/TouchProbe -- watch --mouse --raw

# ⑤ 触摸板
dotnet run --project src/TouchProbe -- watch
```

### 6.3 跑起来后怎么操作

| 模式 | 你要做什么 | 怎么退出 |
|---|---|---|
| 鼠标 | 移动鼠标、按左右中键、滚滚轮 | Ctrl+C |
| 触摸板 | 用手指滑动、单指/双指按压 | Ctrl+C |

### 6.4 `--plain` 模式输出长什么样

```
=== 实时解码 HID 报告 ===
  设备：Gaming 2.4G
  实例 ID：HID\VID_372E&PID_103D&MI_01&COL01\9&7EBF6D8&0&0000
  设备路径：\\?\hid#vid_372e&pid_103d&mi_01&col01#9&7ebf6d8&0&0000#{...}
  报告长度：8 字节（第 1 字节是报告 ID）
  · 显示模式：指针轨迹（设备报的是相对位移）
  · 输出模式：逐行滚动
  ! 这个设备已被系统独占打开（申请读权限被拒绝），ReadFile 走不通。
  · 改用 Raw Input：把窗口注册给系统，让它把原始报告投递给我们（字节内容一模一样）。
  ✔ 报告来源：Raw Input（WM_INPUT）

#12  按键=无   位移 dx=+3 dy=-2
      01 00 03 00 FE FF 00 00
  数据序号  字段                                  我们自己算    系统解码    对照
  ----------------------------------------------------------------------------
  0         Button/Button 1                       0             0           一致
  8         Generic Desktop/X                     3             3           一致
  9         Generic Desktop/Y                     -2            -2          一致
```

**怎么读**：

- `#12` = 第 12 个报告；下一行的十六进制就是设备**原始上报的字节**；
- `位移 dx/dy` = 我们从报告里解码出来的字段值（鼠标报的是"我又移动了多少"）；
- `对照表` = 我们自己按位抠出来的值 vs 系统 API 解码的值，`一致` 就说明我们对描述符的理解正确。

### 6.5 `--async` 模式（学 Task 用）

启动时会告诉你"数据通道"是哪条；按 Ctrl+C 后会打印：

```
✔ 已停止：消费 1183 包，生产 1200 包
· （两个数字不同说明传送带满了丢过旧数据 —— 这是有界 Channel 的“背压”行为）
```

代码在 `Program.RunWatchLoopAsync` 和 `src/TouchProbe/Hid/ReportPipeline.cs`，
左边是同步版 `RunWatchLoop`，两份对照着看最快。

### 6.6 没数据时怎么办

程序每秒打一行心跳，把所有计数都摊给你看：

```
· 等待输入…（3 秒）  鼠标事件=0 筛掉=0 注入来源=0 无编码器丢弃=0 见到设备=（还没有）
```

| 字段 | 含义 | 说明 |
|---|---|---|
| 鼠标事件 | 收到多少个鼠标类事件 | 一直是 0 → 系统没投递（鼠标休眠了 / 没在动 / 选错设备） |
| 筛掉 | 收到但**不是我们要的设备**的数量 | 在涨 → 电脑上有多个鼠标/触摸板，用 `--device N` 指定你要的 |
| 注入来源 | 软件注入（脚本模拟）的事件数 | 只用于排查，不影响正常使用 |
| 无编码器丢弃 | 收到鼠标事件但没提供编码器 | 理论上不会出现 |
| 见到设备 | 实际收到的设备路径 | 用它和上面"设备路径"对比，就知道有没有抓错 |

## 8. 输出怎么读

### 8.1 十六进制那一行

```
01 00 03 00 FE FF 00 00
│  └─┬─┘ └─┬─┘ └──┬──┘
│    │     │      └── 滚轮（0）
│    │     └───────── Y = 0xFFFE = -2（16 位补码）
│    └─────────────── X = 0x0003 = +3
└──────────────────── 报告 ID = 1
```
（还有 1 个字节是 8 个按键位，全 0 = 没按）

### 8.2 字符地图

鼠标模式（`watch --mouse` 不带 `--plain`）：

```
┌──────────────────────────────────────────────────────────┐
│ ·   ·   ·   ·   ·   ·   ·   ·   ·   ·   ·   ·   ·   ·   ·│
│ ·   ░   ░   ░   ░   ·   ·   ·   ·   ·   ·   ·   ·   ·   ·│
│ ·   ·   ·   ·   ░   ░   @   ·   ·   ·   ·   ·   ·   ·   ·│
└──────────────────────────────────────────────────────────┘
```
`@` = 当前位置，`░` = 走过的轨迹，`·` = 背景参考点。
（鼠标报的是**相对位移**，所以位置是我们自己累加出来的——这也是很多图形程序的第一步。）

触摸板模式（`watch`）画的是触点：数字 = 触点编号，位置按逻辑坐标映射到网格。

### 8.3 术语速查

| 词 | 一句话解释 |
|---|---|
| 报告（Report） | 设备一次上报的一包数据 |
| 报告 ID | 报告的第 1 个字节，用来区分不同类型的报告 |
| 位偏移 | 这个字段从报告数据的第几位开始 |
| 逻辑范围 | 这个数值的取值范围（最小值 < 0 说明是有符号数） |
| 用途页 / 用途 | 字段语义编码，如 `0x01/0x30` = X 轴 |
| 集合（Collection） | 描述符里的层级结构；触摸板"一个触点 = 一个逻辑集合" |
| 填充位 | 描述符里没有语义、只用来对齐的常量位 |

## 9. 故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `dotnet: 找不到命令` | 没装 .NET SDK | 装 SDK 10（见 1.1） |
| 编译报 `net10.0 不受支持` | SDK 版本太老 | 升级 SDK，或把 csproj 里的 TargetFramework 改成你有的版本 |
| `list` 里找不到触摸板 | 名字/用途不标准 | 用 `list` 找到最像的那个，`--device N` 手动指定 |
| `watch` 一直"等待输入"且计数全 0 | 没有输入事件 | 鼠标：确认无线鼠标开着并动它；触摸板：手指确实滑一下 |
| 计数里"筛掉"在涨 | 抓到了别的设备 | `--device N` 选你要的那个 |
| `caps` 报"访问被拒绝" | 设备被独占 | 正常现象，看第 2 步的"能否直接读"列 |
| `caps` 崩溃退出（0xC0000374） | 系统结构体尺寸与我们声明不一致 | 见 `docs/03` 第 3.4 节的"结构体标定"方法，改 `NativeMethods.cs` 里的声明 |
| 中文乱码 | 终端编码 | 用 Windows Terminal；程序已强制 UTF-8 输出 |
| 全屏刷新画面错乱 | 终端窗口太小 | 拉大窗口，或改用 `--plain` |
| `--verify` 出现"不一致" | 描述符里有填充位 / 系统字段序号顺序与报告位序不同 | 正常，程序会自动用系统值兜底，见 README「已知问题 2」 |

## 11. 常见问题 FAQ

**Q：为什么不直接读触摸板的 I2C？（项目叫 iic-touch 啊）**
A：因为这根 I2C 总线在机器内部，开机就被 ACPI + `hidi2c.sys` 接管，Windows 用户态**没有**发 I2C 事务的接口（Linux 才有 `/dev/i2c-N`）。这块板子能把 HID 学到极致，学不到 I2C 电气层——详细分析见 `docs/01` 第 4 节。

**Q：为什么拿不到原始报告描述符字节？**
A：这是 Windows 的设计：描述符留在内核，只把**解析结果**给用户态。实测过程（扫 IOCTL、换设备验证）写在 `docs/01` 第 4 节。

**Q：鼠标为什么只能拿到 dx/dy，拿不到原始字节？**
A：Windows 硬规定：订阅鼠标/键盘这类集合时只给 `RAWMOUSE`/`RAWKEYBOARD`。本项目的做法是按描述符把 dx/dy **编码回**报告字节再走同一套解码流程，见 `src/TouchProbe/Hid/MouseReportSynthesizer.cs`。

**Q：程序会不会干扰我正常用鼠标/触摸板？**
A：不会。Raw Input 是"只读订阅"，我们既不屏蔽也不修改输入，只是复制一份原始数据看。

**Q：能读键盘按键吗？**
A：可以，但键盘和鼠标一样属于"只给预处理数据"的类别，需要类似 `MouseReportSynthesizer` 的做法。这留作练习。

**Q：代码注释有多少？**
A：几乎每个文件开头都有一段"这个文件是什么"，关键语法点（P/Invoke、结构体布局、位运算、Task、Channel、RAWMOSE 偏移等）都在代码里现场解释过——**照着代码读，不用另外查资料**。
